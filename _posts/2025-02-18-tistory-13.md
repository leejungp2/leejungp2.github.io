<h3 data-ke-size="size23">How much data to train LLMs?</h3>
<p data-ke-size="size16">시간이 지남에 따라 size, datasets, number of tokens 가 많이 바뀜</p>
<p data-ke-size="size16"><b>Scaling laws</b></p>
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>Kaplan(2020): 10x compute, parameter 5.5x, training token 1.8x
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>175B parameter, 300B token 학습 GPT3, BLOOM &rarr; under trained</li>
</ul>
</li>
<li>Chinchilla(2022)
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>고정 코사인 스케줄러를 사용했기 때문에 위의 결과를 나타냈다고 주장</li>
<li>데이터 크기에 맞는 코사인을 사용하지 않았기 때문에 underestimated</li>
<li>New scaling laws: scale data &amp; model size equally</li>
<li>손실을 맞추려고 하면 데이터, 모델 크기가 선형적으로 증가</li>
</ul>
</li>
</ul>
<p><img src="attachment:ba2cbbbd-27d5-4262-83a5-8e92cf470eec:%E1%84%89%E1%85%B3%E1%84%8F%E1%85%B3%E1%84%85%E1%85%B5%E1%86%AB%E1%84%89%E1%85%A3%E1%86%BA_2025-02-12_%E1%84%8B%E1%85%A9%E1%84%92%E1%85%AE_9.38.50.png" alt="스크린샷 2025-02-12 오후 9.38.50.png" /></p>
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>Chinchilla 이후 ~
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>LlaMA: 7B parameters, 1T tokens</li>
<li>그러나 최적의 &lsquo;계산&rsquo;이 언제나 &lsquo;최적(optimal)&rsquo; 인 것은 아님</li>
<li>비용 뿐 아니라 inference에도 신경써야 함</li>
<li>이로 인해 선호도 정립: 더 적은 데이터로 훈련된 큰 모델 사용 &lt; 더 오랫동안 훈련 된 작은 모델 사용</li>
<li>loss, down stream evaluation 감소</li>
</ul>
</li>
</ul>
<p data-ke-size="size16">&rarr; 훈련하는 데 드는 비용: Inference gets more expensive</p>
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>inference 비용 많이 듦</li>
<li>모델이 커질수록 토큰 처리에 드는 시간이 많아짐</li>
</ul>
<p data-ke-size="size16"><b>Compute optimal is not optimal</b></p>
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>Scaling laws에서 inference cost는 고려되지 않았음
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>smaller models trained longer are more cost effective</li>
<li>Chinchilla scaling laws - x &rarr; pay a &lsquo;compute overhead&rsquo;(훈련하는 동안 더 많은 비용을 지불하지만, 추론하는 동안 비용을 아끼도록)</li>
</ul>
</li>
<li>Harm&rsquo;s law: compute overhead for training past Chinchilla
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>13% overhead(추가 연산), 50% 비용 절감</li>
</ul>
</li>
</ul>
<p data-ke-size="size16"><b>Scaling laws: further reading</b></p>
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>Scaling data-constrained lm - 데이터 제한 언어 모델 확장 논문
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>데이터 크기에 제한이 있는 경우 - 4번 에폭까지 데이터를 반복할 수 있음</li>
<li>공개적으로 사용 가능한 데이터가 거의 없는 도메인에서 유리</li>
</ul>
</li>
<li>DeepSeek LLM: new scaling laws for data
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>scaling behavior가 데이터 품질에 크게 좌우 된다는 것을 발견</li>
<li>다양한 하위집합, 필터링 시도 &rarr; 성능이 달라짐</li>
<li>더 높은 품질의 데이터셋이 있을 경우 데이터 크기가 아닌, 모델 크기에 더 많은 컴퓨팅을 할당해야한다고 결론</li>
</ul>
</li>
</ul>

<h2 data-ke-size="size26">Q&amp;A</h2>
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>What are the consequences of training AI models with synthetic data? Are there any problems? 합성 데이터가 언어의 분포를 잘 대표하는가? 때로는 인간의 low quality data도 필요하다고 생각

<li>이유: 1 모델에 어느정도 편향을 강제로 가하는 것, 2 contamination: 벤치마크와 유사한 형태로 훈련하면 contamination 위험</li>
<li>사람들이 합성 데이터를 보지 못했기 때문에 회의적이었음</li>
<li>합성 데이터가 웹 배포와 동일하지 않은 것은 타당한 지적</li>
<li>자연 + synthetic data 섞이면 좋을 것, human intution is not always suitabl for model</li>
</ul>
</li>
<li>RLHF data more preferable than 비지도 학습 모델?
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>요즘은 RL 거치지 않고, 명령어-솔루션 pair 튜닝만하고 쌍으로 모델 학습시키는 방식</li>
<li>or DPO, ORPO</li>
<li>not necessarily RLHF</li>
</ul>
</li>
<li>multimodal grounding로 인해 model training을 위한 text data의 필요성이 줄어들까요?</li>
<li>Major differences between text vs code

<li>MQA, GQA</li>
<li>ovreall similar, but smaller model 필요</li>
</ul>
</li>

<h2 data-ke-size="size26"><b>Aligning Open Language Models</b></h2>
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>A heavily abbreviated history of language models (LMs)
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>cf) stochastic parrots: 언어 모델이 단순히 데이터를 흉내 내는 역할만 한다는 비판적 시각</li>
<li><a href="https://dl.acm.org/doi/10.1145/3442188.3445922">https://dl.acm.org/doi/10.1145/3442188.3445922</a></li>
</ul>
</li>
</ul>
<p data-ke-size="size16"><b>Can ChatGPT exist without RLHF?</b></p>
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>cf) RLHF(Reinforcement Learning from Human Feedback): AI 모델을 학습시키는 과정에서 인간의 피드백을 활용하여 모델의 성능을 개선하는 데 사용</li>
<li>RLHF 작동 방식
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>기본 모델 사전 학습:
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>AI 모델은 대규모 데이터셋을 사용해 사전 학습(pretraining)됩니다.</li>
<li>이 과정에서 모델은 일반적인 언어 패턴, 문법, 문맥 등을 학습합니다.</li>
</ul>
</li>
<li>피드백 데이터 수집:
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>인간 평가자(annotators)는 모델이 생성한 여러 출력 결과를 보고 이를 평가합니다.</li>
<li>예를 들어, "이 답변이 더 유용하다" 또는 "이 출력이 더 적절하다"와 같이 순위를 매깁니다.</li>
</ul>
</li>
<li>보상 모델 학습:
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>인간 피드백 데이터를 바탕으로 보상 모델(reward model)을 훈련합니다.</li>
<li>이 모델은 출력 결과에 대한 "좋음"과 "나쁨"을 평가하는 데 사용됩니다.</li>
</ul>
</li>
<li>강화학습 적용:
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>훈련된 보상 모델을 기반으로, 강화학습 알고리즘(주로 Proximal Policy Optimization, PPO)을 사용해 AI 모델의 행동 방식을 최적화합니다.</li>
<li>목표는 보상 모델에서 높은 점수를 받는 출력을 더 자주 생성하도록 학습시키는 것입니다.</li>
</ul>
</li>
</ul>
</li>
<li>필요조건은 맞지만 충분조건은 아님</li>
<li>RLHF is a key factor in many popular models, both on and off the record, including ChatGPT, Bard/Gemini, Claude, Llama 2, and more</li>
<li>
<div><img src="https://prod-files-secure.s3.us-west-2.amazonaws.com/5580b69a-8993-4ae0-a8bd-10285493ea97/55fbf851-f195-432c-a77f-2eef453f4424/%E1%84%89%E1%85%B3%E1%84%8F%E1%85%B3%E1%84%85%E1%85%B5%E1%86%AB%E1%84%89%E1%85%A3%E1%86%BA_2025-01-20_%E1%84%8B%E1%85%A9%E1%84%92%E1%85%AE_2.10.28.png" alt="스크린샷 2025-01-20 오후 2.10.28.png" /></div>
</li>
<li>RL is not &lsquo;cost and time effective&rsquo;</li>
<li>proliferation of finetuning models
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>Base models</li>
<li>Aligned, finetuned, preference trained models &rarr; 오늘 강의 초점</li>
</ul>
</li>
</ul>
<p data-ke-size="size16"><b>Some definitions for &lsquo;alignment&rsquo; of models</b></p>
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>Instruction Fine-Tuning (IFT): 모델이 사용자 지시를 따르도록 학습하는 과정 (주로 자동회귀 언어 모델 손실 사용)</li>
<li>Supervised Fine-Tuning (SFT): 특정 작업을 학습하도록 지도 학습 기반으로 모델을 조정</li>
<li>Alignment: 사용자의 요구를 반영하도록 모델을 학습시키는 일반적인 개념</li>
<li>Reinforcement learning from human feedback (RLHF): 인간 데이터에서 ML 모델을 훈련하기 위한 specific technical tool</li>
<li>Preference Fine-Tuning: 사용자의 선호 데이터를 활용해 모델을 미세 조정 (RL, DPO, 기타 손실 함수 포함)</li>
</ul>

<h3 data-ke-size="size23">Chapter 2: Setting expectations &amp; evaluations</h3>
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>Do LoRA methods work with RL?
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>소비자용 GPU에 RLHF가 가능할까?</li>
<li>왜 아무도 좋은 모델을 훈련시키지 않았는가?</li>
<li>제약: LoRA는 대규모 학습에서는 더 좋은 모델을 학습시키기에 한계가 있음</li>
<li>대안: GPU가 많은 사람의 경우 scale하는 것이 더 좋은 방법</li>
</ul>
</li>
<li>Llma 2 chat backlash
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>파이썬 처리 과정의 문제</li>
<li>어떤 모델이 해야하고 하지 말아야 할지</li>
<li>모델이 수행해야 할 작업과 수행하지 말아야 할 작업의 구분.</li>
<li>질문
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>"대화형 모델은 안전해야 하는가?"</li>
<li>"사용자와 적극적으로 의견을 다투는 모델은 적절한가?"</li>
</ul>
</li>
</ul>
</li>
<li>검열되지 않은 모델 Uncensored models
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>데이터셋 내 특정 포인트를 제거하여 검열을 피하도록 조정</li>
<li>모델이 처음부터 &lsquo;검열(censored)&rsquo; 되지는 않았음</li>
<li>목표: 모델이 어떠한 요청에도 거부하지 않도록 수정</li>
<li>방법: 학습 데이터에서 "as a language model..." 또는 "Sorry, ..."와 같은 거부 메시지를 제거</li>
<li><b>Confusion: Not the clearest name for things. The models were never explicitly censored to begin with.</b></li>
<li>Prefer the name <i>filtered</i> or <i>unbiased</i>
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>One of the first models named this way (April 2023): <a href="https://huggingface.co/cognitivecomputations/WizardLM-7B-Uncensored">cognitivecomputations/WizardLM-7B-Uncensored</a></li>
<li>Example models here: <a href="https://huggingface.co/models?other=uncensored">https://huggingface.co/models?other=uncensored</a></li>
</ul>
</li>
</ul>
</li>
<li>Transition period
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>April. 2023: WizardLM v0.1 trained with <a href="https://arxiv.org/abs/2304.12244">EvolInstruct</a> (synthetic data generation), other strong RL math/code models mostly ignored by community, <b>MT Bench 13B: 6.35</b></li>
<li>Jun. 2023: <a href="https://huggingface.co/openbmb/UltraLM-13b">UltraLM 13B</a> trained on new UltraChat dataset</li>

<h3 data-ke-size="size23">Chapter 3: Getting RLHF to work</h3>
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>Review: RLHF objective</li>
<li>
<div><img src="https://prod-files-secure.s3.us-west-2.amazonaws.com/5580b69a-8993-4ae0-a8bd-10285493ea97/579235c4-0a7e-435a-a68a-fe58c49321bf/%E1%84%89%E1%85%B3%E1%84%8F%E1%85%B3%E1%84%85%E1%85%B5%E1%86%AB%E1%84%89%E1%85%A3%E1%86%BA_2025-01-20_%E1%84%8B%E1%85%A9%E1%84%92%E1%85%AE_3.12.33.png" alt="스크린샷 2025-01-20 오후 3.12.33.png" /></div>
</li>
</ul>
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>Primary Questions?
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>보상을 어떻게 구현 implement 할 것인가?</li>
<li>보상을 어떻게 최적화optimize 할 것인가?</li>
</ul>
</li>
<li>Review: Preference (reward) modeling
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>key idea: 보상은 특정 텍스트가 다른 작업 중 선택될 확률에 비례해야 함</li>
</ul>
</li>
<li>해결방법: Gradient Ascent
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>DPO(Direct Preference Optimization)를 사용하는 접근법
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>구현이 매우 간단함</li>
<li>기존 분산 학습 라이브러리와 잘 연동됨</li>
<li>암시적 보상 함수(Implicit Reward Function)를 학습함</li>
<li>하지만, 근본적인 한계가 더 높은 성능을 보장하는 것은 아님</li>
</ul>
</li>
</ul>
</li>
<li>DPO vs RL
<ul style="list-style-type: disc;" data-ke-list-type="disc">
<li>둘은 매우 다른 optimizer</li>
<li>RL: 가치 함수를 학습하여 최적화</li>
<li>DPO: 직접 경사단계 적용</li>
<li>&rarr; 둘 중 하나만 선택되지 않고 서로 보완 가능</li>
</ul>
</li>
</ul>

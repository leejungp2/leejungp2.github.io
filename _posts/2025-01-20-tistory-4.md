<h2><strong>Intuitions on Language Models (Jason)</strong></h2>
<p>Q. Why do LMs work so well?</p>
<p>→ manually inspect data</p>
<p>ex) 폐암의 종류를 분류하는(classify) 프로젝트를 했었음</p>
<ul>
<li><p>but 이 일을 하려면 medical degree 필요하다고 함</p>
</li>
<li><p>논문 많이 읽고, 병리학적 case 많이 접함</p>
</li>
<li><p>How LM are trained</p>
<ul>
<li><p>next word prediction task: 앞에 나오는 단어가 있고, 그 다음에 나올 단어를 예측함</p>
</li>
<li><p>각 단어에 대한 확률 도출</p>
</li>
<li><p>LM은 모든 단어에 확률 부여</p>
</li>
<li><p>손실(loss): 실제 다음 단어와 예측 단어 간 차이</p>
</li>
<li><p><em>→ 첫번째 직관*</em>: next-word prediction = massively multi-task learning</p>
</li>
</ul>
</li>
</ul>
<ul>
<li><p>Example tasks from next-word prediction</p>
<ul>
<li><p>Grammar</p>
</li>
<li><p>Lexical semantics</p>
</li>

</li>
<li><p>Sentiment analysis</p>
</li>

</li>

<p>=next word prediction이 어려움!</p>
</li>
</ul>
</li>
</ul>

<ul>
<li><p>x축이 계산(compute), y축이 손실(loss)로 둘 때, 계산이 증가함에 따라 손실이 선형적으로 감소</p>

<li><p>why does scaling imrove the loss?</p>
</li>
<li><p>비교</p>

</ul>

<h2><strong>Shaping the Future of AI from the History of Transformer (Hyung Won)</strong></h2>
<ul>
<li><p>Goal: Future ↔ History</p>
<p>  <strong>→ important to study the change itself</strong></p>
</li>
<li><p>What does it mean?</p>
<ol>
<li>Identify: 변화를 이끄는 주요 원동력(dominant driving force) 찾기</li>
<li>Understand: 주요 원동력 이해하기</li>
<li>Predict: 미래의 변화 예측하기</li>
</ol>
</li>
<li><p>주요 원동력: 컴퓨팅 비용이 기하급수적으로(exponentially) 감소함</p>
<ul>
<li>어떻게 한 것인가?</li>
<li>teach machines how to think **</li>
<li>incorporate that into</li>
<li>understand in very low level</li>
</ul>
</li>
<li><p>과거 70년간의 AI 연구는 점점 약한 모델링(less structure) 방식으로 발전</p>
<p>  → bitter lesson: 복잡한 구조를 만들기보다 자유도를 제한하지 않는 방식이 더 유용</p>
<ul>
<li>이는 기하급수적으로 감소한 연산 비용 덕분에 가능했음</li>
<li>add more data and computation (i.e. scale-up)</li>
<li>기하급수적으로 연산 비용이 낮아짐 → 더 나은 연구자가 되는 것보다… → leverage 하기 위해 노력해라!</li>
</ul>
</li>
<li><p>구조에 따른 비교</p>

</li>
<li><p>less structure: 더 많은 자유도로, 장기적 확장성이 뛰어남</p>

<h3>Understand the driving force</h3>
<ul>
<li><p>What is transformer?</p>
<ul>
<li><p>입력 시퀀스: input of sequence model; each sequence as a vector</p>
</li>
<li><p>시퀀스 간 상호작용(interaction): dot product of each other</p>
<ul>
<li>if high, semantically more related</li>
</ul>
</li>
<li><p>트랜스포머: 이러한 방식으로 입력 시퀀스를 처리하는 특정 시퀀스 모델</p>
<p>  <img src="https://prod-files-secure.s3.us-west-2.amazonaws.com/5580b69a-8993-4ae0-a8bd-10285493ea97/96b16ddd-b80d-4fb6-a18a-5cc710c7cd04/%E1%84%89%E1%85%B3%E1%84%8F%E1%85%B3%E1%84%85%E1%85%B5%E1%86%AB%E1%84%89%E1%85%A3%E1%86%BA_2025-01-18_%E1%84%8B%E1%85%A9%E1%84%92%E1%85%AE_3.34.25.png" alt="스크린샷 2025-01-18 오후 3.34.25.png"></p>
</li>
</ul>
</li>
</ul>
<ol>
<li><strong>전통적인 Transformer 모델</strong></li>
</ol>
<ul>
<li>encoder(주황색 부분)<ul>
<li>입력 시퀀스의 모든 토큰 간 상호작용을 허용</li>
<li>N번 반복되는 MLP(피드포워드 레이어)로 출력 생성</li>
<li>output = sequence of vectors (representing seqeunce element, words)</li>
</ul>
</li>
<li>decoder(파란색 부분)<ul>
<li>input에 대해 인과적 자기 주의(causal self-attention) 메커니즘 사용</li>
<li>causal self-attention = cannot win training</li>
<li>sequence-sequence mapping</li>
</ul>
</li>
<li>import patterns<ul>
<li>교차 주의 메커니즘(cross-attention): 디코더가 인코더의 특정 레이어와 상호작용</li>
<li>all the layers in decoder attends to final layer of the encoder</li>
</ul>
</li>
</ul>
<ol>
<li><p>encoder-only(BERT)</p>
<p> <img src="https://prod-files-secure.s3.us-west-2.amazonaws.com/5580b69a-8993-4ae0-a8bd-10285493ea97/5cb37ad3-77da-43fb-8fe5-85a1389e78bb/%E1%84%89%E1%85%B3%E1%84%8F%E1%85%B3%E1%84%85%E1%85%B5%E1%86%AB%E1%84%89%E1%85%A3%E1%86%BA_2025-01-20_%E1%84%8B%E1%85%A9%E1%84%8C%E1%85%A5%E1%86%AB_1.12.28.png" alt="스크린샷 2025-01-20 오전 1.12.28.png"></p>
</li>
</ol>
<ul>
<li><p>출력이 단일 벡터로, 입력 시퀀스를 요약</p>
</li>
<li><p>주로 감정 분석과 같은 분류 문제에 활용</p>
</li>
<li><p>시퀀스를 생성하지 않으므로, 장기적으로는 한계</p>
</li>
<li><p>BERT, we had benchmark GLUE</p>
<ul>
<li><p>sequence in - classification layer out</p>
</li>
<li><p>additional structure - give up on the generation</p>
</li>
<li><p>seqeunce to classification label is so much easier</p>
</li>
<li><p>not generating sequence</p>
<p>↔ in the long term not really useful</p>
</li>
</ul>
</li>
</ul>
<ol>
<li><p>decoder-only(GPT)</p>
<p> <img src="https://prod-files-secure.s3.us-west-2.amazonaws.com/5580b69a-8993-4ae0-a8bd-10285493ea97/25eec01a-682b-4747-96d1-fee16cf31813/%E1%84%89%E1%85%B3%E1%84%8F%E1%85%B3%E1%84%85%E1%85%B5%E1%86%AB%E1%84%89%E1%85%A3%E1%86%BA_2025-01-20_%E1%84%8B%E1%85%A9%E1%84%8C%E1%85%A5%E1%86%AB_1.12.45.png" alt="스크린샷 2025-01-20 오전 1.12.45.png"></p>
</li>
</ol>
<ul>
<li>단일 스택 구조로, 입력 및 출력 시퀀스를 모두 처리 가능</li>
<li>decoder only - also be used for supervised learning ↔ concatenate with target</li>
<li>자기 주의 메커니즘(self-attention): 입력과 출력 시퀀스 모두를 처리하며, 교차 주의(cross attention) 메커니즘의 역할을 통합</li>
<li>output is a seqeunce</li>
<li>self attention is serving both roles</li>
<li>both input and target sequences</li>
</ul>
<h3>How different are encoder-decoder and decoder-only architectures?</h3>
<p>→ quite similar</p>
<ol>
<li><p>Share cross and self-attention parameters</p>
</li>
<li><p>Share encoder and decoder parameters</p>
</li>
<li><p>Decoder layer l attends to encoder layer</p>
</li>
<li><p>Make encoder self-attention causal</p>
</li>
</ol>

<h3><strong>Additional structures</strong></h3>
<ol>
<li><p>입력 시퀀스와 출력 시퀀스가 충분히 다를 경우, 별도의 매개변수(parameters)를 사용하는 것이 효과적</p>
<ul>
<li><p>입력과 출력의 구조적 차이가 클 경우, 같은 매개변수를 공유하면 정보의 혼란이나 손실이 발생할 수 있음</p>
</li>
<li><p>Encoder-Decoder 구조</p>
<p>  ex) 예를 들어, 번역 작업에서 입력(영어)과 출력(한국어)은 어휘, 문법, 표현 방식이 매우 다르다. 이 경우, 입력과 출력을 각각 별도의 매개변수로 처리하면 더 효과적인 학습 가능</p>
</li>
<li><p>그러나 별도의 매개변수로 표현하면 더 크고 general한 모델에 대해서 자연스럽지 않음</p>
</li>
</ul>
</li>
<li><p>출력 시퀀스의 각 요소는 입력 시퀀스의 완전히 인코딩된 표현에 주의를 기울일 수 있음</p>
<ul>
<li><p>디코더의 출력 요소가 인코더에서 생성된 입력 요소의 최종 표현을 참고할 수 있음</p>
<p>  ex) 디코더 레이어1이 인코더 최종 레이어에 접근한다면, 원래의 attention 메커니즘에는 차이가 없음</p>
</li>
<li><p>따라서 강연자는 Encoder - Decoder 불필요한 디자인이라고 생각</p>
</li>
</ul>
</li>
<li><p>입력 시퀀스를 인코딩할 때, 시퀀스 내 모든 요소 간(all-to-all) 상호작용이 선호됨</p>
</li>
</ol>
<ul>
<li><p>학술 데이터셋은 입력 길이가 길 수 있지만, 출력(Target)을 길게 만들 수 없는 제약이 있음</p>
<ul>
<li>ex) 텍스트 요약 작업에서 입력 문서는 길지만 요약문(Target)은 짧음</li>
<li>이러한 특성은 E-D 아키텍쳐에 적합</li>
</ul>
</li>
<li><p>오늘날 LM은 입력과 출력(Target)이 모두 길고 복잡한 작업(longer target situation)을 처리해야 함</p>
<ul>
<li>따라서 더 단순한 구조(Decoder-Only)를 채택하는 것이 좋음</li>
<li>더 큰 데이터와 긴 시퀀스를 다룰 수 있는 확장성</li>
</ul>
</li>
<li><p>bidirectional, unidirectional</p>
<ul>
<li>Bidirectional: 입력 시퀀스의 모든 요소가 서로 영향을 주고받으며 학습(ex. BERT)<ul>
<li>모든 입력 토큰 간의 상호작용을 고려하므로 더 풍부한 문맥 정보 학습 가능</li>
<li>다중 회차 대화(multi-turn conversation)에서는 매번 새로 입력을 인코딩해야 하므로 비효율적</li>
</ul>
</li>
<li>Unidirectional: 현재 단어는 이전 단어에만 의존해 학습(ex. GPT)<ul>
<li>현재 단어가 앞선 단어에만 의존하므로 효율적인 학습 가능</li>
<li>Bidirectional 모델은 &quot;Why&quot;(왜 그랬는가?)를 학습하기 위해 &quot;How&quot;(어떻게 발생했는가?)를 고려해야 하지만, Unidirectional 모델은 단순히 연속적인 데이터를 학습하므로 이러한 고려가 필요 없음</li>
</ul>
</li>
</ul>
</li>
<li><p>Conclusion</p>
